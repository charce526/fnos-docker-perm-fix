# 应用实现说明

**Docker权限修复 1.3.0** · 作者：[charce526](https://github.com/charce526)

应用通过飞牛统一网关与受限 Unix Socket 提供管理员界面。Web 服务和任务执行器均以 root 运行；进程分离用于隔离任务生命周期，不表示已经将 Web 服务降权。

## 结构

```text
飞牛管理员入口 → /app/docker-perm-fix → app.sock
  server.js          管理员认证、来源校验、CSRF、接口及静态资源
  control.js         启停、PID 与启动时间核对、安装预检
  worker.js          扫描、计划、执行与复测
  lib/docker.js      Docker 快照、进程身份、组与映射
  lib/policy.js      路径与挂载规则、签名与限额
  lib/tree.js        挂载路径描述符操作、降权访问模拟及路径对象修改
  lib/jobs.js        单任务互斥、进度、超时与持久记录
  lib/storage.js     数据目录、原子记录、审计和进程锁
  public/model.js    四类界面状态、项目分组与选择模型
  public/ui.js       导航、筛选、诊断、预览和任务交互
```

`bin/docker-perm-fix.sh scan` 保留扫描兼容入口，旧的直接 `fix key` 入口已移除。Docker CLI 固定连接本机 Unix Socket，不继承远程 Docker context。

## 扫描与身份

扫描使用完整容器 ID、inspect 快照及重复列表校验；失败或变化不伪装成“没有容器”。Compose 分组读取 `com.docker.compose.project` 和 `com.docker.compose.service` 标签；无项目标签的容器单独列出。

Linux 的普通权限由属主 UID、属组 GID 和权限位决定；飞牛 NAS 还使用 POSIX ACL 记录用户、用户组、掩码和默认 ACL，共享目录通常通过继承 ACL 控制访问。Docker 绑定挂载不复制目录，也不重写这些权限；容器进程仍以宿主机视角的 UID/GID 访问 NAS 上的真实文件。当容器身份与路径属主、权限位、补充组或 ACL 不匹配时，内核会返回 Permission denied。本应用检查并修复的是这个宿主机路径访问差异。

运行身份通过两次 Docker top 进程列表与 /proc 启动标识复核，检查 UID/GID、有效能力和映射，不依赖 cgroup 路径格式。root 进程带文件访问能力时显示“权限不受限”；其他不可靠身份显示“未检测”。停止容器只能在拥有完整非零数字 UID:GID 声明时进入修复；没有 GID 时不猜测。

访问检查从已打开的挂载路径描述符开始，在独立进程设置补充组、GID、UID 后检查读、写和进入权限。目录只检查目录本身，普通文件只检查文件本身，不遍历子项。只读挂载不要求写入；它不检查容器目标父目录、LSM 等全部运行环境，也不把属主不同直接判为权限错误。

界面只显示“容器身份”，不重复补充组、来源和检测细节。它来自宿主机 `/proc` 中的容器工作进程凭据并核对身份映射；停止容器显示启动配置中的数字声明，界面标为“需核对”。

## 界面约定

界面、筛选与项目树统一显示四类结果：**正常、需关注、未检测、检测失败**。后端原始状态继续保留在诊断导出中，避免丢失证据。项目与容器汇总其中最需要关注的状态；没有绑定挂载的容器显示未检测，并计入“未检测”状态卡数量。

项目树和检查结果都按项目名、容器名与挂载路径排序。项目树始终包含所有项目，支持独立搜索和折叠。点击导航会清除结果区搜索与筛选后跳转；批量选择仍使用同一选中集合，隐藏已选项会计入确认计划。结果区不提供额外的排序下拉。

表格使用固定布局与列宽，路径可换行，诊断内容限制高度并内部滚动。窄屏切换为卡片式排列。帮助、工作原理和限制集中到右上角，动态诊断保留在对应项目中；执行确认仍明确展示变更范围。

帮助内容按“Permission denied 成因、应用职责、检查原理、应用侧操作、结果状态、修复边界”组织，便于先判断问题，再执行修复。

## 修复执行

修复只有一种方式：把挂载路径 UID:GID 调整为容器身份，再补读、写或进入权限，ACL 保留。

计划绑定容器、路径、身份和挂载路径摘要，有效五分钟，每批最多 100 项挂载。勾选多项会合并为一个批量任务；每项只产生挂载路径本身的动作。容器可以直接修复，执行前仍重新校验配置、挂载和运行身份。路径解析与修改采用描述符及 O_NOFOLLOW，拒绝链接、特殊对象、硬链接文件和不支持的特殊权限位变更。修改文件属主前检查文件 capability。

系统及 NAS 管理目录、Docker 引擎内部目录、卷根、共享或重叠绑定路径和不支持的文件系统不自动修改。挂载路径内部的子挂载不会进入本次修改范围。缺少 getfacl 时禁用修复。每步记录与验证已完成的变更，部分失败或中断会如实保留；这不是原子文件系统事务。

## 图标与发布

应用中心的 `ICON.PNG` / `ICON_256.PNG`、桌面入口的 `ui/images/icon_64.png` / `icon_256.png`、界面与浏览器图标的 `server/public/app-icon.png` 使用同一母版。详见[图标资料](../assets/README.md)。

从项目根执行 `node scripts/build.cjs --offline`，或在 app 中执行 `bash build.sh --offline`。构建在独立暂存目录安装锁定依赖，核对运行文件、图标、版本与归档权限，成功后发布安装包并清理暂存目录。
