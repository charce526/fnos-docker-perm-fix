## 主要行为变化

- 权限检查显示具体受限对象、操作、身份来源和覆盖范围；不再把同属主 700 根目录、异属主或工具失败直接推断为应递归修复。
- Docker 元数据改用原生 JSON；读取实际进程 UID/GID、补充组、映射与能力集合；不使用 exec id 猜测工作身份，也不保留 root 自动通过或不可信模式回退。
- 修复改为服务器保存的五分钟计划。明确列出路径、目标身份、每个对象变更前后状态，重新核对配置与目录快照后执行。
- 保留 ACL，默认只补目标用户已有对象的所有者权限。显式选择调整属主才改变列明对象 UID:GID；通过 getcap 拒绝带文件能力的属主修改。
- 增加系统子树、卷根、管理目录、Docker 实际 data-root、相等/父子/同 inode 挂载、bind 别名和嵌套挂载保护。逐级描述符打开并拒绝跟随链接；硬链接、特殊对象及特殊 mode 变更保守拒绝。
- 执行前要求容器停止；不自动停止或启动。每个修改对象先同步写元数据快照，再修改并验证；部分完成和中断保留真实结果，不自动回滚。
- 服务只通过受限 Socket 接入；开发端口必须显式开启、只绑定 loopback 且使用独立令牌。增加 CSRF、同源校验、任务互斥、持久状态、进程组超时和审计轮转。
- 界面按容器分组，修正筛选与全选，统计和数值排序一致；忙状态阻止冲突操作，修复结果独立保留并可导出，390px 窄屏使用卡片布局。

## 原 T01–T32 验收范围

T01–T11 的权限/身份逻辑、T12–T16 的边界与快照、T17–T24 的失败协议与任务，以及 T25–T29 的 UI 已有本地策略、虚拟执行或浏览器测试覆盖相应分支。真实 DAC/ACL、mount namespace、root/capability、并发文件系统和磁盘故障必须到隔离 Linux 环境补充。T30 的真实 PID/进程组/安装生命周期、T31 的安装后有效模式及 T32 的 fnOS/x86/ARM 仍需设备验收。Node22 的 Windows 兼容性已实测，不能外推为 Linux 内核测试通过。

已提供 `tests/linux-permissions.test.cjs`，在隔离 Linux root 环境显式设置 `RUN_LINUX_PERMISSION_TESTS=1` 运行。本机跳过的仅是该集成入口，不是把未执行的内核场景计为通过。完整验收步骤见 [维护文档](MAINTENANCE.md)。
